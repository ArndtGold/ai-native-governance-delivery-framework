Missing data is rendered as zero counts and an empty selector, incorrectly suggesting an empty inventory.

## Resolved proposed design

Overview captures only Master Backlog plus containment anchors; it presents stored backlog sections/status/next step, never a computed gate or an invented complete Run inventory. Named opening captures and evaluates exactly the requested Run through existing Core, without loading the backlog overview or evaluating every unrelated Run. Required global Core metadata/dependencies remain included. A deliberate Run/source/context transition creates one replacement immutable dependency capture, returns matching parent/child data with a fresh snapshot identity, and invalidates the preceding selectors. A document body is requested only through a registered opaque selector; Core seal verification may still need that source's bytes earlier. Graph node presentation is requested only when opened; global graph validation remains an evaluator dependency where required.

Extend the existing captured-read owner with bounded access recording for the requested Core operation, freeze the resulting read set, revalidate its contained dependencies (including observed absence and directory enumeration), and replay the projection only from captured bytes. No unobserved path becomes missing by default; access outside the allowed control boundary is sticky-denied. Explicit relevant dependency mutations abort publication. Unrelated historical files outside that read set cannot exhaust the byte budget or stale the view. Drop the old retained capture before constructing the replacement to preserve per-view/aggregate byte ceilings; failed transition retains only labelled prior UI data and requires a new capture, never revives old selectors.

Evolve the private cockpit snapshot input with optional strict run_id and discriminated scope DTOs; no argument defaults to backlog, named input returns the checked Run. Existing run/document/context names remain deliberate scoped transitions with fresh snapshot envelopes and matching parent bundles. Frontend accepts a new snapshot only at an explicitly requested transition, rebinds resource IDs and preserves target/Run/generation checks and return focus. Browser adapters use the same Core transitions; default governance MCP/CLI behavior and canonical filesystem/approval formats remain unchanged. Schema/resource are prepared together, and old cockpit DTO/UI is not declared compatible with the changed pair.
