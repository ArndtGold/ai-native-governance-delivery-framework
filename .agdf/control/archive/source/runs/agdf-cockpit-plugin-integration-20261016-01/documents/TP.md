### Native execution procedures

All N-* routes require the actual Codex desktop/MCP-App surface, installed final plugin and host permissions. The existing isolated CLI E2E may support transport diagnosis, but cannot satisfy UI rendering or the same-key native UI qualification requirement. Never substitute a Playwright fixture, CLI success, tool-list advertisement or model answer for a native observation.

1. N-CLEAN: preserve the actual current installation/config identities. Use the normal existing installer `npm --prefix packages/cli run install:codex -- --accept-plugin-capabilities --json` for the reviewed local candidate only after T-007 and normal host permission checks. Use an actual supported native context with no standalone Cockpit registration, then a fresh Codex session. Observe plugin/provider discovery; open `agdf_cockpit` with the confirmed target and exact optional existing Run; record displayed identity, protocol UI initialize and rendered view, run/document selection, refresh, context action, read routing and teardown. Hash canonical project control/config before and after read-only actions. Wrong/missing project/run is tested against disposable fixture projects. Capture host/client/session/plugin/server/UI/SDK identities, tool origin/namespace, screenshots or host UI observations plus raw protocol/read events. If a separate clean native context is unavailable, record this scenario unexecuted and preserve the current installation until the evidence route can be completed; a current legacy-bearing session is not clean-install proof.
2. N-LEGACY: with an exactly verified owned distinct-key legacy entry, observe the old effective provider and retain its bytes/runtime. Qualify the installed plugin provider under N-CLEAN's render/read requirements for the same target, without claiming the two providers are a finished transition. Validate the matching transition evidence through the existing lifecycle owner; invoke the implemented SD maintenance operation for that exact project/section; reload when required. Observe final normal-context discovery/render/read and the absence of the old effective offering. Verify unrelated settings and retained disabled section/runtime. Use disposable profiles for failure injection; the real entry is retired only after its matching proof.
3. N-SAMEKEY: first establish an actual host-supported isolated native UI context for the same confirmed project. Document the supported isolation mechanism and prove that the original configuration/working installation is untouched and its legacy declaration is absent only from the qualification context. Install the exact final package via the existing installer, under the same stable server key; run N-CLEAN's attribution/render/read checks. Bind that observation and the normal-context plugin/config preconditions in the transition record. Only then use the existing guarded lifecycle transaction to disable the verified old section and activate the qualified candidate; never reconnect with ambiguous providers. Complete fresh normal-context native render/interaction and fault/rollback verification in disposable profiles. If isolation is unavailable, stop this transition with the original route active and record the missing native host context; no temporary alias or pre-proof legacy disablement is permitted.
4. N-LIFECYCLE: in an actual supported disposable native context, apply normal plugin update, disable, re-enable and removal one at a time through existing host/plugin lifecycle controls; reload only when required. Observe the provider offering after each action and compare actual loaded identities, UI availability and preserved foreign/shared-runtime canaries. Real user installation is not removed to run a destructive test. Missing disposable native access leaves that operation unexecuted; lifecycle unit tests remain a separate evidence level.

Native observations are cooperative records with raw evidence, not independent proof of human provenance and never a gate approval. Existing auth/trust must be used without copying secrets into the Run. Host-controlled permission/reload interactions may require Arndt Gold; ask only when that concrete step requires it. Do not end the work merely to ask again for the already authorized local integration.
