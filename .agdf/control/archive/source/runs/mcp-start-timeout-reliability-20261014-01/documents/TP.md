## 3. Test Plan

### Fixed claim/deadline policy and measurements

The executed planning measurement evidence/TP_CLAIM_BASELINE.json used Node v22.22.3 on darwin-x64, the installed package owner and a complete byte-matched runtime copied into a canonical owned disposable directory. Twenty uncontended real claim calls ran full marker/server/dispatcher/SDK proof, durable claim creation and lock release: p95 826.426ms, maximum 895.696ms. Complete-call elapsed time upper-bounds the claim lock hold; it does not measure package acquisition/publication or native host startup. No injected preparation or product mutation was used. The copied claims/runtime were removed only with that owned temporary directory.

The first attempt correctly refused a noncanonical macOS /var temporary-path alias. evidence/TP_CLAIM_BASELINE_PRELIMINARY.json preserves the refusal; the measurement helper now realpaths only its own temp root, with the production containment guard unchanged.

Set the claim contention wait ceiling to **5550ms**, fixed before implementation: ceil((6 * 895.696361 + 150) / 150) * 150. Six holds represent the explicit normal burst of three product clients, each with facade and direct-child acquisition; 150ms is the existing bounded poll interval. The helper's 2850ms proposal counted only three holds; TP accounts for both claim sites. This conservative sizing is a testable planning bound, not a guarantee for arbitrary client count or slow network publication.

The effective wait is min(5550ms, remaining existing publication deadline). Preparation and subsequent claim wait share the existing 30000ms total publication allowance; they may not each restart a fresh full allowance. Never extend that allowance, the 10000ms default Worker deadline, generation qualification 30000ms, generation close 10000ms, existing message/capacity/receipt ceilings or declared host limits. Stop waiting if a lock is no longer exact live contention; reacquisition always reruns current full proof under the same lock. Use existing owner-local deadline accounting, not a new scheduler.

Test immediate acquisition, verified live release at controlled 150/450ms, the last permitted retry before deadline, still-held at/after 5550ms, and a remaining publication budget of 300ms. Deterministic clock/seam tests verify exact arithmetic; real child/lock tests verify actual release/no lock stealing. Scheduler tolerance is only for real elapsed observations (one 150ms poll plus measured event-loop delay reported), never an extra executable wait. Unknown/malformed/foreign locks and real integrity mismatch must refuse without retries or state damage. Network/publication longer than the fixed remaining budget remains a bounded diagnosed failure requiring supported prewarm, not arbitrary deadline inflation.
