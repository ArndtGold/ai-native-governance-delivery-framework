# Clean Implementation Review

## Decision

- decision: `pass`
- review_scope: approved OpenCode-native plugin parity implementation

## Primary solution

The implementation has one primary product path:

1. canonical AGDF skill, router, Runtime Contract and plugin-definition sources remain under `plugin/**`;
2. `sync-package-assets.js` generates native `.opencode/skills/agdf-*/SKILL.md` adapters and a thin `.opencode/AGDF.md` router;
3. `opencode.json` loads the npm plugin, instructions and explicit permissions;
4. `opencode-plugin.js` owns lifecycle/status/compaction context only;
5. `.agdf/control/` remains the durable repository source of truth.

This fixes the root cause of the parity gap: OpenCode previously exposed generated subagents while its native skill discovery had no AGDF entries. The implementation replaces that representation with native skills instead of adding another surface beside it.

## Evidence

- all nine canonical skills are generated and discovered by installed OpenCode `1.17.13`;
- native agent discovery reports no generated AGDF agents after regeneration;
- repository search reports no remaining product/documentation reference to the old agent-only surface outside the bounded migration code and its test;
- plugin/status checks point to `.opencode/skills/agdf-gate-check/SKILL.md`;
- runtime integrity and aggregate package tests pass;
- TP Review reports 10/10 tasks `fully_done`.

## Fallbacks retained

### Owned legacy-agent migration

- rationale: repositories generated by the previous release may contain AGDF-owned `.opencode/agents/agdf-*.md` files; leaving them would create a parallel routing surface after native skills are generated;
- boundary: removal applies only during explicit `opencode-repo` regeneration and only to known canonical names with the exact generated description, `mode: subagent` frontmatter and canonical skill heading;
- target state: native `.opencode/skills/agdf-*/SKILL.md` only;
- exit condition: once a repository has regenerated and its owned legacy agents are removed, the migration path is a no-op;
- evidence: focused smoke test proves owned-file removal and preservation of unrelated user agents.

### Existing global config-directory installer

- rationale: the existing AGDF `opencode` command provides deterministic config and package-loadability status evidence; adopting the newer native `opencode plugin` installer without an equivalent status contract would weaken current verification;
- boundary: no second AGDF command, parameter or runtime policy was added;
- target state: reconsider native installer delegation only when OpenCode exposes a stable machine-verifiable installed-package/status contract;
- exit condition: a future approved slice can replace the internal installer while preserving or improving `opencode-status` evidence.

This is retained Brownfield behavior, not a new runtime fallback in the native skill path.

### Status JSON version-1 alias

- rationale: existing `opencode-status --json` consumers may read `repository_surface.gate_check_agent`;
- boundary: the deprecated field and the new `gate_check_skill` field resolve to the same native skill path and share one status owner;
- target state: consumers migrate to `gate_check_skill`;
- exit condition: removal is permitted only in a future explicitly versioned status schema;
- evidence: focused smoke test asserts schema version, alias equality and path validity; package documentation names the deprecation.

## Workaround or shim risk

- risk: low
- finding: the legacy migration and status-v1 alias are finite compatibility shims, not target architecture; neither routes execution nor decides product policy.
- advisory: `agdf-gate-check` and `agdf-*` permission patterns are surface identifiers repeated at adapter boundaries. Current smoke/runtime probes cover them, but a future prefix change must update plugin detection and permission expectations together.

## Parallel-structure risk

- risk: none observed in the delivered state
- canonical policy owner: `plugin/**`
- generated OpenCode files: adapters only
- old generated AGDF agents: removed from package output and explicitly migrated from target repositories
- user-owned OpenCode agents: preserved and not treated as AGDF policy owners
- capability classification: remains single-owner and fail-closed at `instruction_only`

## Brownfield fit

- decision: pass
- existing package export, CLI targets, config protection, status model, generator and test owners were extended in place;
- no new installer command, policy engine, gate calculator, Runtime Contract copy or capability evaluator was introduced;
- documentation and Pages copy were updated at their existing owners rather than adding a new OpenCode-only guide.

## Missing evidence

No missing evidence blocks solution-integrity review. Cross-version OpenCode behavior and model-independent gate enforcement remain outside the approved target state and are explicitly visible risks, not hidden fallbacks.
