### Master Backlog: deterministic writing versus observation authority

The existing canonical writer remains the owner of backlog mutation. Its run-step path serializes the Run lock then the shared Backlog lock, compares expected revisions/current bytes, writes each file by atomic replacement and uses the Run commit point plus transaction journal/recovery for the multi-file result. Requalify existing regression coverage; the cockpit must not add a writer or a second synchronization policy.

The current approveRunGate path writes the sealed Run and does not atomically refresh the Master Backlog. prepareBacklog preserves an existing status unless an operation explicitly supplies a replacement, and a missing backlog can be reported without an update. Thus safe deterministic write mechanics do not guarantee every pointer is complete, unique, or synchronized after every gate operation. T-001 records these precise boundaries; unsupported/missing/duplicate pointer behavior remains visible through the approved parser/reading scope.
