## Working Modes And Effective State

- working_modes: active preparation; active corrective work; explicit status inspection; awaiting human decision; awaiting external host observation; technical/integrity block; interrupted/resumed delivery.
- effective_state_by_mode:
  - Active preparation: the selected run permits a named internal prerequisite; its completion is recorded and dependent work begins only after reevaluation.
  - Active correction: the selected run permits a bounded correction or evidence/review obligation; source-approved scope and required owners still constrain it.
  - Explicit status: current observation only; no delivery activation, writer or implicit continuation.
  - Human decision: the exact target/run/gate/revision/artefact is ready for deliberate review; a newly presented response is required.
  - External observation: a candidate and sequence are prepared; host observation is still missing and no success is claimed.
  - Technical/integrity block: a precise failed condition prevents safe work; the outcome identifies the responsible actor and bounded recovery without overriding the failure.
  - Resume: prior work is context; current binding, source integrity and permission must be checked again before dependent work.
- visible_state_types: working; missing internal prerequisite; invalid unapproved input; correction validated; decision ready; external action required; unchanged failed correction; authority/integrity blocked; prior observation stale; resumed current state.
- effective_state_authority_by_mode:
  - Preparation/correction/resume: existing canonical Core evaluation, approved sources and normalized review-gap owners establish permitted work; analysis and progress text grant no permission.
  - Human decision: existing exact presentation and deliberate approval process establish approval authority.
  - External observation: the recorded evidence obligation and observed candidate identity establish what is and is not proven; connection changes and tool success do not approve a gate.
  - Status/block: the existing evaluation and error source establish current truth; the user-facing explanation cannot repair integrity or invent permission.
- primary_state_presentation_owner_by_mode:
  - Working: the agent communicates brief progress and the meaningful next outcome under the existing interaction contract.
  - Decision/status/block: the existing canonical operational or approval presentation supplies the state, actor and action.
  - External observation: the existing qualification/evidence owner explains candidate, action sequence and missing proof; no separate acceptance authority.

## Activation, Blockers, Recovery And Transitions

- activation_paths: An explicit delivery request, exact pending gate approval or unambiguous active-run continuation activates the existing route. Inspection, comparison and ordinary questions remain read-only. The same selected scope is retained across correction and resumption.
- blockers: missing/ambiguous target or run; missing/stale/foreign approval; changed approved intent; unavailable authority; invalid seal/runtime; unresolved material user question; unchanged failed correction; required inaccessible host observation.
- recovery_paths:
  - For an eligible missing prerequisite, the existing internal owner prepares and records it, then current control is reevaluated without user restart.
  - For a permitted malformed unapproved input, identify source/field/expected/observed condition, correct through its owner, validate and reevaluate. Invalid calls remain rejected; unchanged failures stop rather than loop.
  - For a material user decision, explain the specific missing choice together once; preserve useful drafts without claiming readiness.
  - For a required host action, provide the prepared candidate and bounded observation sequence before asking for reconnection; preserve applicable evidence and record remaining gaps.
  - For an interruption or transient failure, support deliberate retry/resume through the existing binding. A retry grants no approval and cannot change the target or widen scope.
- relevant_state_transitions:
  - Approved upstream gate -> internal prerequisite needed -> owner completes/validates/records -> reevaluation -> next permitted draft -> exact approval presentation -> wait.
  - QA-revise -> classify using existing normalized finding -> permitted implementation/evidence owner, upstream decision route or external observation -> refreshed reviews/QA only when required proof exists.
  - Malformed input -> specific diagnosis -> allowed correction -> validation success -> same-scope continuation; unchanged failure -> precise stop and named actor.
  - Candidate prepared -> named external action -> actual host observation -> version-bound evidence; candidate changed -> explicit fresh obligations with unchanged evidence applicability preserved.
  - Explicit status -> current report -> end inspection; no active work is invented.
  - Interruption -> fresh binding and evaluation -> unchanged authorized work resumes or changed prerequisite becomes visible.

## Proposed PRD Acceptance Criteria

- Distinguish absent internal input from malformed readiness data and from a genuine requirement/authority gap.
- For each pre-PRD/QA-revise state, state the next actor and whether execution continues, needs a human decision or awaits an external observation. A terminal result cannot claim immediate work that does not occur.
- Keep supported invocation fields/skill options and exact source fields valid; expose concrete corrections while retaining fail-closed rejection.
- Prepare host identity and observation steps before the necessary external handoff; preserve evidence provenance by version and affected obligation.
- Demonstrate zero extra restart prompts for the fixed permitted cases, separately count legitimate decisions/external actions and retain all control and evidence.
- Verify negative authority/integrity/status cases, rendered localization and source/package/native evidence independently.
