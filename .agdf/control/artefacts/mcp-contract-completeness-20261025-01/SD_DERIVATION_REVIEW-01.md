## Material design decisions

All eight SDD IDs are stable and are referenced by the Acceptance Traceability table. Each PRD criterion appears exactly once there. The chosen SDK seam, policy ownership, schema/help factoring, full-result/public projection, generation/error limits and metadata strategy are resolved before_sd decisions. No architecture question or product choice is hidden in later_tp; only concrete test inventory and native execution configuration are deferred to the named TP owner.

The additional decorator is a single narrow adapter around the SDK-owned connection, not an independent JSON-RPC parser, dispatch registry, request queue or permission source. The Core input interpreter remains on expanded schemas; factoring does not require a new reference interpreter. Result-schema checking extends the existing finite structural checker without creating a caller-configurable JSON Schema engine or a second eligibility policy. The public output projection remains intentionally bounded like the existing inspection envelope, while full structural checking and family authority retain their owners.

There is no deliberately accepted technical debt or new unsupported effect. If the public seam, variant coverage or measured final compositions cannot satisfy the specified constraints, the design explicitly routes the gap back to SD instead of authorizing a private hook, weaker schema, enlarged limit or extra runtime. These are future verification obligations, not claims of current delivery.
