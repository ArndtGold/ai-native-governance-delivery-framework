### Native case, isolation and evidence boundary

Extend the existing host runner/guard rather than adding another daemon, installation manager or evidence schema. The RUN_MODEL case uses process-only candidate configuration and the existing account without copying/printing credentials, changing HOME/CODEX_HOME, changing global tool permissions, installing globally or upgrading the CLI/model. Reuse existing bounded time/session controls; do not loosen them for a pass. Capture the actual preflight state and the original before/after configuration identity.

Each of the two sessions runs the same bounded current-model journey to expose obvious non-repeatability without creating a benchmark: discover the candidate's current tools/help; explicitly initialize a fresh target; create and inspect a current Run/material; exercise an explicitly source-bound planning handoff in the disposable fixture; inspect canonical inventory/document paths; observe an exact controlled original-operation replay; and request inspection of a separate disposable old-store fixture to verify explicit unchanged refusal. Fixtures may contain explicitly synthetic prerequisite gate records created through current test owners; they are never described as the maintainer's approval or copied from this governing Run as live authority. Scripted operation responses are test input only. Actual process-kill/recovery and all negative combinations remain the deterministic process suites, not extra model sessions.

Do not use the default native installer cohort or diagnostic app-only probe as a substitute for normal production MCP. The candidate must be normally built/owned, not a hand-patched direct-import server. Native claims depend on actual CLI events plus candidate/state/receipt observations; model prose alone is not proof. If normal candidate loading cannot be achieved with the existing permitted process-only mechanism, the native obligation is unfulfilled and must be resolved before claiming the planned qualification. Missing auth is not permission to log in or obtain credentials.

At execution, freeze the actual package/source fingerprints and record the actual CLI/model/reasoning/OS/Node tuple before reservation. Expected availability at planning was Codex 0.163.0 and Node 22.22.3; a changed tuple is reported and assessed before use, never silently relabeled. Do not claim other native hosts or Codex Desktop tested. Keep ordinary adapter/Windows/Linux CI results separate.

### Verification timing, reuse and stopping rule

Run targeted owner tests as the corresponding changes land. Reuse applicable scenario intent and existing test helpers, not historical green results as proof of changed code. Where feasible, show the original targeted condition failing for the intended reason before its correction; source-model removal itself uses explicit before/after behavior and required negative cases rather than tests that mirror implementation.

Before QA, finish the affected integrated functional/process/UI checks, normal generated package/integrity/compatibility/eval/timing proof and actual Codex CLI qualification, then the existing mandatory reviews. CD_TESTS.md groups commands/results and links retrievable raw logs once; the same real result can support several criteria. Retain original failed outcomes and original evidence limits. Do not create a per-proof form or duplicate whole logs into multiple reports.

Mandatory full PR/merge CI follows the updated canonical test inventory after separately authorized VCS actions. Correlate its actual head SHA, workflow commit, all paginated checks and conclusions. No fixed job count is promised because removed obsolete suites change inventory; coverage must still equal that inventory. CI pending at local QA is a declared merge-only evidence gap, never a green result or permission to merge. No automatic local verify:commit, second full verify:ci run, new Nightly suite or broad native multi-host matrix. An additional full run needs a concrete changed-input/uncertain-impact/failure reason.

Stop technical collection when mapped claims have valid source/environment-bound proof, applicable findings are resolved and contradictions cleared. Broaden only for a changed dependency, uncovered obligation or new contradiction. QA/UAT/OR and human decisions remain required even when automated checking is complete. Any product/design gap routes to PRD/SD under the existing normalized-gap policy; an implementation/evidence gap cannot be hidden as a late TP assumption.
