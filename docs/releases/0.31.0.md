# AGDF 0.31.0 — Companion Core und MCP-Fortsetzung

AGDF 0.31.0 bündelt die Änderungen seit dem veröffentlichten Tag `agdf-v0.30.0`. Der
Companion erhält eine gemeinsame Status- und Ereignisquelle in Core. Die MCP-Übergaben
führen Agenten direkter durch die Arbeitsschritte, die der aktuelle Run erlaubt. Projektspezifische
Brand-Vorgaben lassen sich in prüfbare UX-Kriterien übersetzen.

Diese Notes beschreiben den vorbereiteten Quellstand. Für den Paketstand, die Veröffentlichung
und native Host-Nachweise gelten die jeweils eigenen Prüfungen im [Release-Prozess](../../RELEASE.md).

## Gemeinsame Statusansicht und Ereignisse für den Companion

Core erzeugt eine lesende Run-Ansicht aus dem kanonischen Kontrollzustand. Sie enthält den
aktuellen Lieferstatus, den nächsten zulässigen Schritt und Diagnosehinweise. Die
Runtime-Schnittstelle `run-view --dir <Projektpfad> --json --language de` kann optional
mit `--run <Run-ID>` auf einen einzelnen Run begrenzt werden.

Der Claude-Companion nutzt diese Ansicht und das begrenzte lokale Ereignisjournal. Das
Journal meldet etwa eine angeforderte oder erfasste Freigabe und kann bei gebundenen
Dokumenten Hinweise zur überprüften Quelle liefern. Maßgeblich für Freigaben und
Run-Zustand bleibt der kanonische Kontrollbestand. [PR #59](https://github.com/ArndtGold/ai-native-governance-delivery-framework/pull/59) · [PR #61](https://github.com/ArndtGold/ai-native-governance-delivery-framework/pull/61)

## Gebundene MCP-Aufrufe fortsetzen

MCP stellt für unterstützte Arbeitsabläufe einen konkreten nächsten Aufruf bereit. Der
Agent übernimmt die gebundene Referenz und füllt nur die vorgesehenen Eingaben. In
unterstützten, vom Plugin verwalteten CLI-Sitzungen bleiben vorbereitete Referenzen
innerhalb ihrer ursprünglichen Gültigkeit über einen Sitzungswechsel hinweg nutzbar.
Der Wiederaufnahmeweg verwendet bei unklarem Ergebnis die ursprüngliche Operation.
Fehler, die schon vor der Weiterleitung eines Befehls auftreten, werden als solche
ausgewiesen. [PR #57](https://github.com/ArndtGold/ai-native-governance-delivery-framework/pull/57) · [PR #58](https://github.com/ArndtGold/ai-native-governance-delivery-framework/pull/58)

Nach der Umsetzung führt die Fortsetzung zu den noch erforderlichen Reviews vor QA.
Beim Abschluss werden der registrierte OR und seine QA-Quelle gezielt geladen. Für
strukturierte Runs nach UAT liefert ein erfolgreicher Inline-Upload oder der abschließende
Multipart-Seal genau einen vorbereiteten OR-Abschlussaufruf. Beim Upload bleibt der Run
offen. Erst der separate Aufruf registriert den exakten Bericht und schließt den Run ab.
Bei erneutem Upload desselben Berichts unter derselben Bindung bleiben Operations-ID und
technische Bestätigung erhalten. [PR #62](https://github.com/ArndtGold/ai-native-governance-delivery-framework/pull/62) · [PR #63](https://github.com/ArndtGold/ai-native-governance-delivery-framework/pull/63) · [PR #64](https://github.com/ArndtGold/ai-native-governance-delivery-framework/pull/64)

## Brand-Vorgaben als prüfbare UX-Kriterien

Die Initialisierung legt für neue Projekte ein neutrales Brand-Arbeitsblatt an. Hat ein
Projekt eine maßgebliche Brand-Quelle festgelegt, können UX-Analyse und PRD daraus
beobachtbare Kriterien ableiten. Das Lösungsdesign verknüpft seine Entscheidungen mit
diesen Kriterien. Die Quellenbindung schützt die nachvollziehbare Zuordnung, auch wenn
eine Projektdatei noch nicht in Git versioniert ist. [Markenquellen im Handbuch](../handbook/de/03-typische-arbeitsablaeufe.md#markenquellen-in-überprüfbare-ux-kriterien-übersetzen)
