## NAME

`prd-definition` - derive and clarify a bound unapproved product specification

## SYNOPSIS

`/prd-definition` [`--help`|`-h`]

## DESCRIPTION

Derives useful product scope and observable acceptance criteria from the approved UR and required
analyses after bound dispatch. Preserves material open decisions and asks focused clarification.
Explicit draft revision uses canonical recording; every change requires fresh presentation.
Reuses UI preview findings during product clarification, maps adopted behavior to acceptance
criteria and keeps mockup feedback separate from PRD approval and implementation evidence.
Checks the exact durable preview version referenced by UX and preserves any unmet explicit UR
preview requirement instead of closing it from a chat rendering or unsupported feedback.
Prepares the preview review task and criterion mapping for the canonical PRD presentation; it does
not create another approval card or claim unsupported preview binding or host access.
